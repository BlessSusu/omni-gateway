# Phase 4 — 超大规模与集群内转发

| 属性 | 值 |
|------|-----|
| 版本 | v1.0 |
| 状态 | **规划中** |
| 前置 | [Phase 3](./PHASE3.md) 业务协议与下行增强稳定 |

> 注：第三期已将 **gRPC 网关间下行转发**、**一致性哈希** 从原「第三期可选」调整为本期核心议题。

---

## 阶段目标

当分节点 Kafka Topic + Redis 会话索引在 **节点数 > 20** 或 **Redis QPS / Topic 管理成本** 成为瓶颈时，引入集群内数据面转发，并可选降低 Redis 依赖。

建议周期：**4～6 周**（依赖第三期压测与容量报告触发）。

---

## 交付清单

| 能力 | 说明 |
|------|------|
| **gRPC DownlinkForward** | 统一下行入口 → 查路由 → 非本机则转发至目标节点执行 `DownlinkDispatcher` |
| **网关间 mTLS** | 服务间证书、超时、熔断 |
| **一致性哈希环** | `deviceId → slot → node`，扩缩容只迁移约 1/N 设备 |
| **Redis 降载（可选）** | 哈希主路由 + Redis 仅作故障恢复索引 |
| **国密（按需）** | SM2/SM4 TLS 双栈端口，合规单独立项 |

---

## 里程碑

```
M23 gRPC 下行转发服务 + 客户端
    └─► M24 一致性哈希与扩缩容迁移
            └─► M25 压测 PT-09/10 + 多节点混沌
                    └─► M26 国密（可选）
```

---

## 验收标准（草案）

- [ ] 业务仅写统一 Topic，经入口节点转发，**仍仅 1 节点**写 socket  
- [ ] 扩容 1 节点后下行成功率不降，路由迁移可观测  
- [ ] 网关间 gRPC P99 &lt; 50ms（同 AZ）  

---

## 明确不做

- 替代 Kafka 的内部总线  
- 全量 Session 跨节点 replication
